2.0 Part A: Hardware Microarchitecture Synthesis

The physical layer implements the 16-bit Von Neumann computer architecture across three modular chips:

  • CPU.hdl: Implements the Hack execution engine. Executes A-instructions (MSB=0) and C-instructions (MSB=1). Evaluates ALU arithmetic/logic outputs against status bits zr (zero) and ng (negative) to drive 8 conditional jump states in the Program Counter (PC).
  • Memory.hdl: Arbitrates the unified 32K address space across Data RAM (RAM16K, 0x0000–0x3FFF), Screen buffer (Screen, 0x4000–0x5FFF), and Keyboard register (Keyboard, 0x6000) using DMux4Way and Mux4Way16.
  • Computer.hdl: Top-level system chip integrating ROM32K program store, CPU, and Memory.

3.0 Part B: Python Assembler Architecture & Specialization

5.0 Engineering Defect Resolution ("One Mistake I Fixed")

Encountered Anomaly: During initial deployment of Box.asm, the rendered graphic appeared slanted diagonally across successive scanlines instead of maintaining a solid vertical rectangular geometry.

Root Cause Analysis: The Hack display scanline comprises 32 16-bit memory words (512 pixels). For seed K = 38, the box width is 48 pixels (3 words). Within the inner rendering loop, the base pointer addr is advanced by 2 word(s) using M=M+1. An initial stride offset of 30 was erroneously introduced. Consequently, each row advance equaled 2 + 30 = 32 words per row rather than the required 32, inducing an cumulative horizontal phase error of 1 word (16 pixels) per scanline.

Corrective Action Applied: The stride offset constant was recalibrated to @30 words. Adding 30 to the already incremented address satisfies the equation:

Row Advance = 2 (Word Incs) + 30 (Stride Constant) = 32 Words (512 Pixels)

This eliminated the drift and stabilized the graphic into a rock-solid, vertically aligned 48×20 pixel rectangle. Additionally, arithmetic syntax was locked to canonical M=D+M to conform strictly to the Hack ALU datapath operand routing specification.
