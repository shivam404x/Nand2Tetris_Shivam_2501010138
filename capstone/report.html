2. Part A: Computer Microarchitecture Construction

The Hack computer architecture was assembled using three foundational HDL modules adhering to the Von Neumann structural model:

  • Memory.hdl: Dispatches the 32K address space across data RAM (0x0000–0x3FFF via RAM16K), screen memory map (0x4000–0x5FFF via Screen), and the keyboard memory-mapped register (0x6000 via Keyboard). Demultiplexing of write signals and multiplexing of output bus lines is governed by address bits address[13..14].
  • CPU.hdl: Features an ALU, two internal registers (A and D), and a Program Counter (PC). Implements 16-bit instruction decoding: MSB = 0 dictates an A-instruction (immediate data / address load), while MSB = 1 governs C-instructions (ALU computation, destination routing, and conditional branching based on ALU status flags zr and ng).
  • Computer.hdl: Top-level integrated chip wiring ROM32K instruction fetch with CPU processing datapath and Memory read/write infrastructure.

3. Part B: Python Assembler Design & Extra Feature (K mod 3 = 2)

A custom two-pass assembler was engineered in Python (assembler.py) to translate symbolic Hack assembly language into binary machine instructions:

  • Pass 1 (Lexical Stripping & Symbol Table Generation): Eliminates line comments (//) and whitespace. Tracks ROM instruction address indexing. Encounters of pseudo-instructions such as (LABEL) record the label mapping in the symbol table.
    Special Feature (K mod 3 = 2): Duplicate Label Warning
    The parser records the first declaration line of every label. If an identical label re-appears, the assembler logs a non-fatal warning without crashing:
    Warning (Line 7): Duplicate label '(LOOP)' defined! First defined at line 4.
  • Pass 2 (Code Generation): Resolves numerical and symbolic A-instructions (allocating user variables sequentially to RAM 16 onward: color=16, addr=17, rows_left=18). Translates C-instructions into 111 + comp(7b) + dest(3b) + jump(3b). Exports full symbol table to symbols.txt.

Verification Suite: Successfully verified against all standard benchmark test programs: Add.asm (6 lines), Max.asm (16 lines), Rect.asm (25 lines), and Pong.asm (27,483 lines). Binary outputs matched the official Nand to Tetris reference assembler bit-for-bit.

4. Part C: The Box Assembly Program (Box.asm)

Box.asm creates an interactive graphics driver that continuously monitors keyboard input (RAM[24576] / KBD). When any key is pressed (KBD != 0), a solid black box is drawn at Row 38. When released (KBD == 0), the box is erased to white.

5. Critical Engineering Mistake Encountered & Resolved

During initial testing of Box.asm with the Python assembler, an arithmetic syntax error occurred at the row stride computation:

Encountered Failure: Error: Line 97: invalid comp expression 'M+D' in instruction 'M=M+D'

Root Cause: Although addition is commutative mathematically, the Hack ALU microarchitecture physically hardwires input X to the D register and input Y to memory operand M (with control bits c1..c6 = 000010). Consequently, the official Hack hardware specification strictly defines canonical addition as D+M. Writing M+D caused the parser to reject the computation string.

Corrective Action: In Box.asm, the instruction was updated to M=D+M. Additionally, assembler.py was updated to incorporate symmetric aliases (M+D, A+D, M&D, M|D) into its internal computation table, making the assembler fault-tolerant and backward-compatible.
